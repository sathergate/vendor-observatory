# 2025-03-14: Sync Bundle — benchmarks.prod to Lakebase Postgres

## Goal

Bridge the gap between the benchmark pipeline (which writes to Delta tables in `benchmarks.prod`) and the webapp (which reads from Lakebase Postgres via PostgreSQL wire protocol). The webapp needs benchmark data in its expected schema, served through Lakebase synced tables.

## What we built

### 1. New Databricks Asset Bundle: `data/sync/`

Created a full bundle from scratch, modeled after `data/benchmark/`:

- **databricks.yml** — Bundle config with variables for `catalog`, `schema`, `source_schema`, `warehouse_id`. Two targets: dev (`sync_dev`) and prod (`sync`). Same workspace as the benchmark bundle.
- **pyproject.toml** — Hatchling-based wheel for the `sync` package.
- **resources/adapt_for_webapp.job.yml** — Spark job scheduled every 30 minutes. Runs the adapter transform.
- **resources/setup_synced_tables.job.yml** — One-off job (no schedule) to create Lakebase synced table definitions.

### 2. adapt.py — Core transform job

Reads from `benchmarks.prod`, writes to `benchmarks.sync` with CDF enabled (`delta.enableChangeDataFeed = true`). Four adapter tables:

| Adapter Table | Source Tables | PK | Rows |
|---|---|---|---|
| `sessions` | `raw_transcripts` | `id` | 2,628 |
| `observations` | `observations` + `worker_queue` (for `work_category`) | `(session_id, vendor_canonical_id, mention_type)` | 5,298 |
| `response_context` | `response_context` + `worker_queue` (for `prompt_id`) | `(session_id, prompt_id)` | 2,628 |
| `prompt_metadata` | `worker_queue.prompt_metadata_json` (parsed) | `prompt_id` | 219 |

Key design decisions:
- Built a shared `session_prompt_lookup` view (joining `worker_queue` to `raw_transcripts` on `transcript_path`) once at job start, reused across all four table syncs.
- All writes use MERGE (upsert) keyed on primary key for idempotency.
- Had to add GROUP BY deduplication on the composite PKs because the source data had duplicates that caused `DELTA_MULTIPLE_SOURCE_ROW_MATCHING_TARGET_ROW_IN_MERGE` errors. Used `ANY_VALUE()` for non-key columns and `MAX(confidence)` for the confidence score.

### 3. setup_synced.py — Lakebase synced table creation

Uses the Databricks REST API directly (not the SDK dataclass) because the Python SDK doesn't yet have `database_project`/`database_branch` fields. The SDK's `SyncedDatabaseTable` only supports `database_instance_name`.

The Lakebase target:
- Project: `7c463349-06ed-4208-afb0-2eb2f4ad58b1`
- Branch: `br-misty-water-d82np7cl`
- Database: `databricks_postgres`

Tom configured the synced tables manually after we hit the API field issue. The resulting Postgres tables are named with a `_synced` suffix: `sessions_synced`, `observations_synced`, `response_context_synced`, `prompt_metadata_synced`.

### 4. Webapp pointed to synced tables

Updated `apps/web/src/lib/db.ts` and `apps/web/src/lib/query-engine.ts`:
- Added table name constants at the top of each file (`T_SESSIONS`, `T_OBSERVATIONS`, `T_RESPONSE_CONTEXT`, `T_PROMPT_METADATA`)
- Replaced all 86 table references across both files
- Had to convert ~22 regular strings (`"SELECT..."`) to template literals (`` `SELECT...` ``) where the replace_all had incorrectly left `${T_...}` inside double quotes

## Deployment timeline

1. Built wheel with `uv build --wheel`
2. Deployed to dev: `databricks bundle deploy -t dev` — validated successfully
3. Deployed to prod: `databricks bundle deploy -t prod`
4. Ran `setup_synced_tables` — failed 3 times:
   - **Attempt 1**: `ModuleNotFoundError: No module named 'databricks.sdk.service.database'` — SDK version too old on cluster. Fixed by pinning `databricks-sdk>=0.60` in job dependencies.
   - **Attempt 2**: `BadRequest: Must specify either database instance name or both database project and branch!` — SDK dataclass missing project/branch fields. Switched to raw `w.api_client.do("POST", ...)`.
   - **Attempt 3**: Same error with raw API — the field names `database_project`/`database_branch` weren't being recognized. Tom configured manually.
5. Ran `adapt_for_webapp` — failed twice:
   - **Attempt 1**: `DELTA_MULTIPLE_SOURCE_ROW_MATCHING_TARGET_ROW_IN_MERGE` on observations — LEFT JOIN to lookup table created duplicate rows. Added `ANY_VALUE` + `GROUP BY` dedup for observations.
   - **Attempt 2**: Same error — source `observations` table itself has duplicate PKs. Added full GROUP BY deduplication on the composite PK.
   - **Attempt 3**: Success. All 4 tables populated.
6. Tom set up the Lakebase synced tables manually, resulting in `*_synced` table names.
7. Updated webapp to point at `*_synced` tables. TypeScript compiles clean.
8. Pushed both commits to main.
